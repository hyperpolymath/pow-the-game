*Private research project.* Exploring Steam Workshop, Steamworks API, and
other gaming-platform networks as substrates for distributed proof-of-work
computation and combinatorial problem solving.

== Core Idea

Steam has tens of millions of concurrent players and a Workshop modding
ecosystem. Games expose scripting APIs (Lua, C#, custom DSLs). The hypothesis:

> Can we use game mods and platform APIs to distribute computational
> workloads — proofing, search, optimisation — across the players/machines
> already running these games, without those machines being explicitly
> enrolled as compute nodes?

This is not crypto mining. It is research into whether gaming infrastructure
can be repurposed as ambient distributed computation — similar in spirit to
BOINC/SETI@Home but embedded in games people are already playing.

== Research Questions

. *Distribution*: Can Steam Workshop mods carry workload fragments? Can
  multiplayer game state act as a shared message bus?
. *Incentive alignment*: How do you reward players/modders for compute
  contributed? In-game currency? Leaderboard credit? Opt-in only.
. *Problem classes*: Which problems are tractable this way? SAT/SMT fragments?
  Graph search? Cellular automata? Monte Carlo simulations?
. *Platform viability*: Steam first. What about Minecraft Fabric/Forge,
  Roblox, Garry's Mod, Factorio's circuit network?
. *Proofing*: Can results be independently verified without trusting any
  single node? What formal verification techniques apply?

== Candidate Platforms

[cols="2,1,3"]
|===
| Platform | API / Mod system | Notes

| *Steam Workshop*
| Steamworks SDK (C++/Rust via steamworks-rs)
| Largest distribution surface; Workshop for code delivery

| *Garry's Mod*
| GLua (Lua 5.1)
| Extremely flexible; Workshop-delivered mods run client-side Lua

| *Factorio*
| Lua mod API + circuit network
| Turing-complete in-game; real compute potential in circuit networks

| *Minecraft (Fabric)*
| Java mod API / Kotlin
| Huge install base; note: Java/Kotlin banned — investigate JNI bridge to Rust

| *Roblox*
| Luau (typed Lua)
| 100M+ MAU; sandboxed but scriptable

| *Custom via Steamworks*
| steamworks-rs (Rust)
| Direct SDK access without any specific game dependency
|===

== Architecture Sketch

----
[Problem source] → fragment → [Steam Workshop / mod delivery]
                                          ↓
                              [Game client running mod]
                                 (player machine)
                                          ↓
                              [Compute fragment result]
                                          ↓
                          [Verification / proof check]
                                          ↓
                              [Aggregation layer]
                                          ↓
                              [Solution reconstructed]
----

Key components to design:

* *Fragmenter*: decompose a problem into independently solvable units
* *Carrier*: deliver fragments via Workshop/mod API
* *Worker*: lightweight compute kernel embedded in mod
* *Verifier*: independently check results without re-running full work
* *Aggregator*: reconstruct solution from verified fragments

== Technology Stack

Following link:.claude/CLAUDE.md[Hyperpolymath Standard]:

* *Steamworks bridge*: `steamworks-rs` crate (Rust)
* *Mod workers*: Lua (Garry's Mod/Factorio), Luau (Roblox)
* *Core logic*: Rust
* *Orchestration*: Gleam (BEAM — fault-tolerant aggregation)
* *Formal verification*: Idris2 (problem decomposition proofs)
* *Configuration*: Nickel
